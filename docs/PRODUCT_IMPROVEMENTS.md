# 产品改进方案（2026-10-10）

> 更新：迭代 1 已完成（见文末「已完成」）。本文档保留完整规划，未完成项继续按原优先级排期。

基于对 `src/App.tsx`、`src/components/**`、`server/**`、`api/**` 的代码审查，以及在线上环境对全部页面的实际走查。

## 结论：现在有三个"假闭环"

| 名义上的能力 | 实际状态 | 学生/老师感受到的结果 |
| --- | --- | --- |
| 单元测评（闯关） | 输入框非空即得分（`ChallengeModule.tsx:43-48`），提交后立即跳回首页，参考要点永远看不到（`App.tsx:3211`） | 测评没有反馈价值 |
| 错题本 + 今日复习包 | 只展示、只增不减，"立即复练"跳到的是课时页而不是原题（`App.tsx:3133-3140`）；复习包取"最近 3 条"而非"今天到期"（`App.tsx:944-966`） | 复习无从下手，动机为零 |
| 教师班级看板 | 读的是**管理员本机 localStorage**（`ManagementModule.tsx:114-118`），学生数据从未上云 | 生产环境下永远看到 0（线上实测：学生人数 0、趋势全 0） |

另有两个"看起来能用但没在用"的地方：统计页的"综合准确率"是 `已完成课时/(错题数+已完成课时)`（`Statistics.tsx:40-42`，线上什么都没做时显示 100%）、听写音频走浏览器 TTS 而不是已有的 Azure 神经语音（`DictationModule.tsx:46-51`）。

## 一、让学习闭环真正闭合（最高优先级，学生端）

| # | 改进 | 为什么 | 工作量 |
| --- | --- | --- | --- |
| A1 | **闯关真判分 + 结果页**：按题型比对答案；句子/口语题复用 `startPronunciationAssessmentSession` 与 `buildSpeakingFeedback`；拆成"提交 → 结果页（逐题对错 + 参考要点）→ 返回" | 这是唯一的单元测评，现在等于没有 | 中 |
| A2 | **错题重练闭环**：`MistakeRecord` 加 `resolved / retryCount / dueAt / smLevel`；"立即复练"直接把原题传给对应模块（听写定位到该题、语法高亮该题）；通过则销账 | 把"展示错题"变成"消灭错题"，这是 K12 最刚需的回路 | 中 |
| A3 | **听写成绩沉淀**：完成条件改为"每题至少作答一次"（现在最后一题答错会永远卡在未完成，`DictationModule.tsx:67-69`）；结束页给正确率 + 错题清单 +"只练错题"；成绩写回 `studyState` | 现在切单元即丢，老师学生都看不到趋势 | 小-中 |
| A4 | **听写改用 Azure 神经语音 + 0.75x/1x 复听** | 现在依赖学生设备有没有英文语音包，音质与口音不可控 | 小 |
| A5 | **弱词/弱句一键回练**：统计页弱词 chips 可点击（现在只是不可点的 span，`Statistics.tsx:180-188`）；朗读页加"只练低于 75 分的句子"模式 | 反馈到练习的最后一跳缺失 | 中 |
| A6 | **听力专项模块**（新）：听音选词（同单元词做干扰）、课文挖空听写、听后选择/判断 | 现在唯一的"听"是拼写型听写，缺少理解型听力；初中听口考试里"听"是最大分项 | 大 |
| A7 | **整篇朗读/背诵**：总览页课文加"通读全文"（连播 + 整篇一次录音），用词级覆盖率算完成度 | 现在只有单句，练不了连贯与背诵 | 中 |
| A8 | **AI 外教纠错闭环**：`/api/ai/chat` 返回结构化 `reply + corrections[] + followUp`，前端渲染纠错卡并写入错题；底部"关键词/句式模板/参考范文"三个死按钮接真实数据；教材陪练模式下评测参考文本改成目标句（现在是学生自己的输入，等于自我复读评分，`App.tsx:2106`） | 这是产品名称里的"AI 外教"，目前只是聊天 + 单句评分 | 中-大 |

```
DELETE /api/classes?id=xxx                # 教师：删班（连带成员与该班作业）
POST   /api/class-members                 # { classId, userId }
DELETE /api/class-members?classId=&userId=
GET    /api/homework?classId=xxx          # 教师视图：作业 + 每个学生的完成情况
GET    /api/homework                      # 学生视图（同一路径按角色分流）：自己班级的作业 + 自己的完成情况
POST   /api/homework                      # { classId, textbookId, unitId, title, taskKeys[], dueAt? }
DELETE /api/homework?id=xxx
```

> 约定：这三个资源都刻意保持「/api/ + 单段路径」，因为 Vercel 的 catch-all 只覆盖一层路径，多层路径在生产会直接 404（血泪教训）。新增接口也请遵守。
