# 语音评测引擎评估（2026-10-10 更新）

背景：朗读评测的打分链路存在客户端集成缺陷（连续识别只取最后一段，见 `SPEECH_PIPELINE_REVIEW.md`），已修复，并已用真机探针验证。
本文回答两个问题：

1. 如果要换引擎，国内商业引擎与 Azure 的差别是什么；
2. 如果走开源自建，能做到什么程度、代价是什么。

## 〇、真机验证结论（先说结果）

用同一句教材句子做了对照实验（TTS 合成 + 加噪 + 中文口音代理样本，区域 `eastasia`）：

| 条件 | Azure 发音评测 | 开源 GOP-lite（wav2vec2 字母级） |
| --- | --- | --- |
| 美音、干净 | acc 97～99 / comp 100 | 96 |
| 美音 + 噪声 | acc 99 / comp 100 | 18 |
| 中文口音、干净 | acc 71 / comp 86 | 27 |
| 中文口音 + 室内低通噪声 15dB | acc 82～83 / comp 93 | — |

**结论：Azure 引擎本身可靠（重口音 + 真实室内噪声下仍有 82+ 的准确度），"识别率低"来自我们自己的集成问题与采集质量，不需要换引擎。**
开源方案的内容识别可用（能定位读错的词），但发音分未经标定，对重口音会给出人类不会给的极低分，不能直接替代商用评测。

## 一、当前引擎（Azure Pronunciation Assessment）

- 用法：浏览器 → 我们的 `/api/speech-token`（现已有 9 分钟缓存）→ Azure WebSocket，音频实时上行。
- 优势：分数经大规模学习者语料标定，准确度/流利度/完整度/音素级结果齐全，支持 `en-US` / `zh-CN` 等；抗噪、抗口音表现明显好于未标定的开源模型；不需要自建算力。
- 实测：探针 `sessionStarted`（含一次未缓存 token 获取 + WebSocket 建连）0.87～0.96s；停止后连续识别补发分段 ~0.44s、一次性识别 0.56～2.34s。
- 风险：中国大陆访问海外区域，TLS + 首字节握手 1.2～1.4s（本机经代理）；线上 Vercel 函数默认在 iad1，学生取 token 需要跨境往返一次。
- 本机实测区域握手（⚠️ 本机当前网络疑似走了代理，只能说明"握手成本量级"，不代表学生真实网络）：

| 区域 | TLS 握手 | 首字节 |
| --- | --- | --- |
| westus2 | 0.50～0.67s | 0.72～0.98s |
| eastus | 0.60s | 0.85s |
| japaneast | 0.71s | 1.00s |
| koreacentral | 0.79s | 1.10s |
| eastasia（香港，当前使用） | 0.85～1.03s | 1.18～1.41s |
| southeastasia（新加坡） | 0.95s | 1.31s |
| chinaeast2（Azure 中国/世纪互联） | 1.56s | 2.10s |

结论：**每次新建会话的握手开销是 0.5～2s 量级**（这也是 token 缓存、连接前预热的意义）。区域选择要用目标学生网络实测，`chinaeast2` / `chinanorth3`（世纪互联运营）需要单独的 Azure 中国账号。

## 二、国内商业替代

| 项目 | 腾讯云智聆口语评测 SOE | 讯飞语音评测（流式版） |
| --- | --- | --- |
| 语言/题型 | 中英文，单词/句子/段落/自由说 | 中英文，单字/词/句/篇章 |
| 反馈粒度 | 准确度(GOP)、流利度、完整度、重音、音素 | 准确度、流畅度、完整度、声韵调型等 7 维 |
| 接入方式 | HTTP/WebSocket（需签名，建议服务端代理） | WebSocket 流式（需 AppId/ApiKey/Secret 签名） |
| 计费 | 后付费 0.005 元/次（≤20 词算 1 次）；套餐包 3～4 元/千次；默认并发 20，≤50 并发免费 | 创建应用后每日 500 次免费额度；正式套餐价格以控制台为准 |
| 延迟 | 国内节点，握手通常几十毫秒级 | 国内节点，同上 |
| 主要收益 | 中国大陆延迟大幅低于海外 Azure；分数同样是标定过的商用模型 | 同上，且儿童/成人分模型对 K12 更友好 |

## 三、开源自建实测（本机跑通）

方法：`facebook/wav2vec2-base-960h`（字母级 CTC）+ `torchaudio.forced_align` 对参考句做强制对齐，
取每个字母在最佳路径上的平均后验概率作为 confidence（GOP-lite），再按词聚合。脚本见
`scripts/open-source-gop-eval/score.py`（Python 3.11 + torch 2.14 + torchaudio 2.11 + transformers 5.19）。

样本用 macOS `say` 生成（同一句教材句子）：

| 样本 | 时长 | GOP-lite 分 | 对齐覆盖率 | 最差词 |
| --- | --- | --- | --- | --- |
| good.wav（美音 TTS，正常朗读） | 3.65s | **96.1** | 53.3% | FAMILY 81 / SIX 89 |
| wrongwords.wav（把 breakfast 读成 lunch） | 3.41s | 83.1 | 51.8% | **BREAKFAST 0.0** / MY 86 |
| noisy.wav（+5dB SNR 噪声） | 3.65s | 60.3 | 43.4% | THEN 14 / BREAKFAST 23 |
| truncated.wav（只读前半句） | 1.83s | 23.1 | 76.9% | GET/UP/SIX 0.0 |
| accented.wav（中文语音读英文，重口音代理样本） | 5.04s | **27.4** | 29.9% | I 0.2 / MY 0.8 / UP 11 |

单条 5 秒音频的推理耗时：**0.04～0.45s（本机 10 核 CPU，无 GPU）**。

可以得到的结论：

1. **内容维度可靠**：读错词能精确定位到 BREAKFAST=0，漏读半句时后半段全部归零 —— 用来做"漏读/多读/读错"的反馈完全够用，而且不花钱、不怕断网。
2. **发音分数不可直接使用**：重口音样本被压到 27 分，说明未标定的字母级后验概率会重罚"口音重但可听懂"的学生。教学场景里这种误伤比"分数偏高"更糟。要能当分数用，必须
   - 升级到音素级（phoneme-level）GOP，用音素对齐而不是字母；
   - 用带人工评分的学习者语料（如 SpeechOcean762、L2-ARCTIC）做回归/标定，让分布对齐人评；
   - 针对中国学生的母语迁移错误（th/s、v/w、词尾辅音丢失等）单独调；
   - 维护中英文词典与 G2P（中文还需拼音/声调）。
3. **算力不是瓶颈，标定才是**：推理单句 0.1s 级别，CPU 即可；真正的成本在数据与算法迭代，以及自建服务的运维（模型版本、扩缩容、监控）。

## 四、建议路线

```
真机探针已验证：Azure 引擎本身可靠（重口音 + 室内噪声 acc 82+）
        │
        ├─ 大多数情况 ──→ 保持 Azure，改做集成修复（已完成）与部署优化：
        │                   1) 部署 token 缓存与新的停止/合并逻辑
        │                   2) Vercel 函数区域换到 hkg1（贴近 eastasia）
        │                   3) 用真实学生录音回归：PROBE_INPUT=xxx.wav npm run probe:speech
        │
        ├─ 若真实录音仍普遍低分 ──→ 先查采集端（麦克风/环境/音量/是否耳麦），
        │                           再做录音质量提示；这不是换引擎能解决的
        │
        └─ 只有出现"必须国内节点/成本/合规"这类明确需求时才考虑换：
                ├─ 省事 + 低延迟 ──→ 腾讯 SOE（0.005 元/次，服务端代理接入）
                ├─ K12 打分风格 ──→ 讯飞语音评测（每日 500 次免费额度可先验证）
                └─ 数据自主/长期省钱 ──→ 自建开源：先用它做"内容核对"（漏读/多读/读错），
                                          发音分等音素级 GOP + 学习者语料标定后再接管
```

短期最划算的组合：**Azure 出分 + 我们自己在客户端做内容核对（漏读/多读/读错）**，因为内容核对不需要标定数据 —— 这一版已经在做（`aggregatePronunciationSegments` 里的 LCS 对齐）。

## 五、复现方式

```bash
# Azure 真机探针（需要 key / token / 线上 token 端点，见脚本头部说明）
npm run probe:speech

# 合并打分逻辑单测
npm run test:speech

# 开源 GOP 评估
cd scripts/open-source-gop-eval
uv venv --python 3.11 --python-preference only-managed
uv pip install torch torchaudio transformers soundfile numpy
.venv/bin/python score.py audio/good.wav audio/accented.wav
```
